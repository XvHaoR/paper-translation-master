# 论文翻译大师 Zotero 插件 0.3

直接在 Zotero 中选择文献进行 OCR 和翻译，在原生 PDF 标签页内对照阅读。
OCR 与译文分别保存为 Zotero 附件；再次查看已有版本无需启动服务或重新处理。

## 安装与启动

从 [Releases](https://github.com/XvHaoR/paper-translation-master/releases) 下载最新 XPI，
在 Zotero → 工具 → 插件／附加组件 → 从文件安装中选择它，重启 Zotero。
旧版用户直接安装新版替换；插件保留原有身份与附件标签，已有结果仍可使用。

首次使用 OCR 的 Windows 用户请下载同版 Setup.exe，双击运行，点击「安装 OCR 引擎」。
安装器自动下载独立 Python、OCR 依赖与模型，并执行识别自检；完成后插件自动发现环境。
在「工具 → 论文翻译大师 → 设置」中可以点击「检测已安装引擎」和「保存设置」，无需手填路径。
支持硬件、首次下载、预览版验收范围见 [安装说明](../docs/INSTALLATION.md)。

主窗口顶部点击「启动 OCR」，或提交处理任务时按需启动。启动阶段显示实际进度，
就绪后进度条消失；失败在工具栏显示原因，不阻塞界面。
需要翻译时在设置中填写自己的大模型接口地址、模型和 API 密钥，保存并测试连接。
OCR 本身不要求翻译密钥，翻译由用户手动触发。

源码开发者可执行 `python zotero/build.py` 生成本地开发包，或用 `--portable` 生成可分发包。
高级设置仍支持手动选择项目目录、Python 路径及现有 WSL FastDeploy 后端。
公开发行包不包含开发者本机目录或 Python 路径。

工具菜单中可以停止由插件启动的服务；任务处理中禁止停止。关闭 Zotero 或停用插件后，
后台启动器监控 Zotero 主进程并通过独立租约控制生命周期；模型加载期间退出或强制关闭 Zotero 也会触发清理。
Windows 使用 Job Object 清理整个 API 子进程树。WSL 模式在持有项目独占启动锁时管理专用模型服务，
包括上次会话遗留的热模型；退出时停止整个模型服务和保活进程，通常需要数秒至十几秒。
原本由其他启动器提供的兼容 API 仅复用，插件不会停止它。
默认服务地址为 `http://127.0.0.1:8765`。端口被旧服务或其他程序占用时，自动选择空闲端口，
确认新版服务就绪后记住新地址；无需关闭原服务，也不会结束占用端口的进程。

## 文献列表：选择处理与查看状态

- 选中文献或 PDF，右键 → 论文翻译大师 → **OCR 选中文献** 或 **翻译选中文献**。
  支持多选排队；选择论文条目时使用首选 PDF，选择具体 PDF 则处理该附件。
- **OCR 状态**、**翻译状态**两列默认显示，也可以在 Zotero 原生列选择菜单中开关。
  两列独立显示未处理、排队、处理中、已完成、失败可重试或待下载。论文父条目也显示其附件的处理状态。
- 在设置或工具菜单勾选 **新文献添加后自动 OCR**，只会处理此后新添加的 PDF，等待文件下载后执行。
  该选项不会批量处理历史文献；**翻译始终手动触发**。
- 从文献列表提交的 OCR 和翻译均在后台排队，完成后不自动打开 PDF 标签页；可通过「查看 OCR 版本」「查看已保存译文」自行打开。
- **强制重新 OCR（忽略所有识别缓存）**：即使已有附件、已完成服务任务或模型原始缓存，也重新执行识别。
  连续多次点击并完成后再次执行，都会实际重新识别；旧附件仍可保留。
- **清除 OCR 结果（保留 PDF 和译文）**：取消该 PDF 的排队/活动任务，释放占用的阅读窗口，
  将该 PDF 的所有 论文翻译大师 OCR 附件移入 Zotero 回收站。保留 PDF、批注、译文和其他附件；
  下次 OCR 强制绕过缓存。清除操作本身不启动 OCR 服务；服务端原始缓存作为历史数据保留，但不用于这次重新识别。
  右侧 OCR 面板也提供「重新 OCR」「清除 OCR」。

## 阅读器：对照、仅 OCR、译文与字号

打开原生 PDF 标签页，顶部工具条新增三个直接可点击的按钮（原文、对照、OCR）：

- **原文 PDF**：原生 PDF 阅读。
- **原文 / OCR 对照**：默认左侧 PDF、右侧 OCR，保留原生 PDF 阅读和批注功能。
- **仅 OCR 版本**：隐藏 PDF，只显示 OCR 阅读面板。

工具条的 **⇄** 交换左右位置；拖动中间分隔线调整宽度，也可聚焦分隔线后用左右方向键调整。
OCR 面板提供识别、翻译、版本查看、清除、Markdown 导出与设置；译文面板另外提供逐段双语和仅译文选项。
没有 OCR 版本时会显示提示；执行识别后自动保存。翻译复用 OCR 结果，完成后保存译文并显示。

**字号**支持 `A−` / `A+`、直接输入 **12–40 px** 和重置为 17 px。
字号对 OCR 与译文均生效，在对照和仅 OCR 模式下均可调整，重新打开后保留。
这项设置不改变左侧原生 PDF 的缩放。

0.2.4 移除嵌入阅读器中的下拉框和原生弹出菜单，直接点击按钮切换模式；不再依赖弹出层坐标与焦点。

## 0.2.15 在窗口中勾选要处理的论文

点击文献列表上方的 **批量 OCR** 或 **批量翻译**，先打开论文选择窗口。
无需在主列表里提前多选；原本选中的论文会预先勾选，但只以窗口中的最终勾选为准。
打开窗口或取消不会启动服务、识别或翻译。点击 **开始 OCR / 开始翻译** 才提交勾选的论文。

窗口默认显示当前文献列表，也可切换到整个当前文献库，并按标题、作者或年份搜索。
列表分别显示 OCR、翻译状态；支持选择本页、选中全部筛选结果、只选未完成和清空勾选。
无 PDF、PDF 尚未下载或文献库只读的论文会说明原因并禁用勾选。
原有 OCR 和翻译右键入口也使用同一选择窗口；强制重新 OCR 通过窗口中的明确选项控制。

**全部任务都在后台处理，即使只勾选一篇，也不会自动打开阅读标签页。**
窗口内状态会更新，主工具栏保留批次进度；关闭选择窗口后，已提交的任务继续执行。
完成后按需打开论文阅读，避免批量处理产生大量标签页。

## 0.2.14 批量处理与阅读外观

在文献列表中点击搜索框旁的 **批量 OCR** 或 **批量翻译**；0.2.15 起先打开上述选择窗口。
右键菜单和工具菜单也支持多选。父条目与其 PDF 同时选中时自动去重；无 PDF 的条目会跳过并汇总提示，
单篇失败后继续处理剩余文献。主工具栏显示批次完成数、排队数及成功/失败计数，批量操作不逐篇打开标签页。
已有结果直接复用；批量翻译会为尚未 OCR 的文献先识别再翻译，仍由你手动触发。

同一 Zotero 会话内复用已启动的文档服务及模型，不在每篇开始前重新加载。
自有进程由进程退出监控判断存活；单次短暂的 HTTP 检查失败不再触发模型重启。
启动时的实际 OCR 自检也会先重试，连续失败后才恢复模型。关闭 Zotero 后仍清理由插件启动的进程。

**仅 OCR** 模式中点击 OCR 或译文只选中段落，不展开 PDF；明确点击块上的 **对照 PDF** 才切回对照界面。
原先保存的页面同样适用，无须重新识别或翻译。

在 **设置 → 阅读字体与颜色** 分别设置 OCR 原文与译文的字体、文字颜色，点击 **保存阅读外观** 立即应用到已打开的窗口。
可选常见字体或输入本机已安装的字体名；留空使用系统字体。文字颜色可自选，也可设为自动跟随明暗主题，
译文默认不再固定为蓝色。外观偏好在重启和切换版本后保留，不启动 OCR 或调用翻译。
原有 A−/A+、字号输入、公式复制及双向对照保持独立。

## 0.2.13 OCR 校正与版面类型

在 OCR 面板点击 **编辑 OCR**，选中一个内容块即可编辑该块的 Markdown。
可以修改正文、公式、表格和图注，调整章节标题层级，或在指定段落前插入 `## Main` 等标题。
类型标签在选中或悬停时显示，区分论文标题、章节标题、正文、摘要、图注与表注；原始 OCR 的版面类别保留。
新增标题没有 PDF 原文区域；已有段落保留编号、坐标以及修改前的原文，继续支持双向对照。

选中多余图片后点击 **删除图片**，也可按 Delete；保存前可撤销，保存后可再次编辑并选择 **恢复原始 OCR**。
点击底部 **保存修改** 生成新 OCR 附件，旧 OCR、旧译文、图片资产和原 PDF 均保留。
**取消编辑** 丢弃本次草稿。编辑与保存仅运行短时本地 Python 渲染程序，不启动模型或调用翻译服务。
已有旧版附件如本机仍保留对应版本的 OCR 数据，可直接进入编辑，无须重新识别；
新版附件自带完整编辑数据，不依赖服务缓存，换机后仍可修改。

修改后，旧译文仍可查看，状态显示 **原文已修改**；点击 **翻译** 会基于当前校正版本生成新译文。
删除的图片不会被重新组合回译文中，OCR 与译文的 Markdown 导出均以各自当前保存版本为准。
即使服务缓存丢失，修改过的 OCR 也会直接上传保存的文本与图片快照用于翻译，不重新 OCR。

## 0.2.12 跨栏段落的多个原文区域

- OCR 合并跨栏段落却只保存首个坐标框时，通过 PDF 自带文字层核对原文起止及内容一致性，补齐遗漏的栏或下一页区域；分别标注各个矩形，避免用大框覆盖旁边无关正文。
- 直接点击缺失的原文区域也能定位回完整段落；OCR、逐段双语和仅译文共用同一原文映射，隐藏英文不影响定位。
- 对已有保存页直接生效，不重新 OCR 或翻译，不修改原 PDF。恢复结果在当前阅读器缓存，重复点击复用结果。
- 扫描件没有文字层、起止匹配失败或内容不一致时保留已知坐标，不猜测额外区域。

## 0.2.11 定位与显示解耦

- 「开启段落高亮／关闭段落高亮」明确显示当前可执行的操作。开关只控制区域框选和背景淡化，关闭后 PDF 与 OCR／译文的双向定位仍然可用；重新开启会恢复当前段落的高亮。
- PDF 坐标与高亮独立到 `modules/comparison.js`；样式、阅读模式、原生字号分别更新，样式更新失败不再阻断定位和模式切换。
- 阅读消息连接在加载保存页前绑定，并通过握手同步初始显示状态；不再把保存页元数据当作内容已加载，也忽略旧窗口的迟到响应。
- 正文点击只负责段落定位，不再触发译文模式和样式更新；连续切换 OCR／译文、字号和排版后坐标保持一致。
- 已保存的 OCR 和译文直接使用，无需重新识别或翻译。

## 0.2.10 紧凑阅读与简化操作

- 移除「修复显示」、右键修复和「启用 OCR 对照」入口；新生成的 OCR 默认支持 PDF 双向段落定位、复制 LaTeX 和导出 Excel，无需翻译或额外启用。
- 压缩段落容器、正文及双语之间的边距，减少段落工具按钮的空白；OCR、双语和仅译文统一使用紧凑排版。
- 已保存的页面在 Zotero 中打开时直接应用新样式，无需重新处理。新导出页也包含相同样式，可独立离线阅读。
- 极早版本缺少坐标的 OCR 仍可查看，若需对照请点击「重新 OCR」。

## 0.2.8 字号调节

- OCR、双语和仅译文使用 Zotero 内嵌浏览器原生文字缩放，字号不再依赖阅读脚本加载。原 PDF 和图片不缩放。
- A−、A+、重置和数字输入统一调整 12–40 号文字；输入有效数字和点击上下箭头立即生效，无需先点击其他位置。
- 切换 OCR／译文、关闭重开文献后保留字号；已有保存页直接生效，不必重新 OCR 或翻译。

## 0.2.7 译文操作简化

- 移除「升级译文显示」入口。译文处理保留「删除译文」和「翻译」；「看译文」仍可离线打开保存结果。
- 更换 OCR 后，需要重新翻译时先删除该语言译文，再点击「翻译」。新翻译使用当前 OCR，并绕过旧译文及段落翻译缓存；PDF、OCR 和其他语言译文保留。

## 0.2.6 译文管理、逐段双语与 PDF 区域对照

- 右键文献 → 论文翻译大师 → **删除当前语言译文**，或在阅读面板点击「删除译文」。该语言的 HTML 和 Markdown 所有历史版本移入 Zotero 回收站；保留 PDF、OCR、其他语言译文和批注。再次手动翻译会绕过旧译文及段落缓存，实际重新翻译。
- 阅读译文时，选择 **逐段双语**（每段英文在上、译文在下）或 **仅译文**；模式会记住。图片、公式和表格不重复堆放。
- 在「对照」布局中，左侧保留 Zotero 原生 PDF，右侧可查看 OCR、仅译文或逐段双语。
  点击右侧段落，或该段的「第 n 页 · 对照 PDF」，跳到 PDF 对应区域并框选、淡化其他内容；点击 PDF 区域也可定位右侧对应块。
  「开启／关闭段落高亮」只控制聚焦效果，不关闭定位。操作不写入 PDF 或创建批注；拖动分隔线和交换左右仍可使用。缺少区域坐标的旧识别块只跳到对应页，不猜测区域。
- 在公式上悬停可点击 **复制 LaTeX**，复制公式源码；表格上方提供 **导出 Excel**，保存页顶部也可导出全部表格。
  Excel 使用与网页版相同的 `.xls` SpreadsheetML 格式，保留单元格文本。公式复制、表格导出、模式切换和区域定位均可离线使用。
- 新保存的结果直接具备这些功能。旧译文可继续离线查看，或点击「删除译文」后再「翻译」，基于当前 OCR 生成新版译文。

## 0.2.5 阅读器恢复与重复查看

- Zotero 对恢复中的、尚未加载的标签页会暂时返回空 reader；插件等待原标签加载完成，避免 `_initPromise` 报错和重复创建标签页。
- 阅读模式等待原生 PDF 初始化后再调整布局，保留原 PDF 内容、批注与页码。遇到之前已空白的标签页，关闭该标签后重新打开。
- 字号脚本使用每次启动独立的 resource 地址；重复点击「看译文」仍读取同一个已保存版本。
  模块加载或字号调整失败不再阻断 OCR/译文查看。
- OCR 漏掉定界符的 `LAI_{young}`、`CO_{2}` 等明确下标/上标，在导出的 Markdown 和 HTML 中补全公式定界符。
  保留代码、链接、文件名模板和已有公式；不修改原 PDF 或原始识别 JSON。
- 新生成的 OCR 已包含段落定位和图表公式显示。已保存的旧译文保持原文件，可继续离线查看。

## 已保存版本的图表与公式修复

0.2.3 修复了官方公式已经带 `$$` 时再次包裹定界符的问题，以及旧 IR 把每个子图指向整页图片目录导致的重复导出。
优先采用 PaddleOCR 官方 `large` 策略保留整图外框；若检测结果只有多个相邻子图、没有外框，
则在导出时根据同一编号图注与连续图块，从源 PDF 保留完整区域，包括子图编号和公共图例。
不同编号图注之间的图片不合并，原始识别 JSON/Markdown 保留。

新 OCR 自动按上述规则导出，已保存结果可继续离线阅读。

官方依据：[PaddleX 整图/子图框合并](https://paddlepaddle.github.io/PaddleX/3.0/practical_tutorials/layout_detection.html#44)、
[PaddleOCR-VL 参数](https://paddlepaddle.github.io/PaddleX/3.7/en/pipeline_usage/tutorials/ocr_pipelines/PaddleOCR-VL.html)、
[MathJax 公式定界符](https://docs.mathjax.org/en/latest/input/tex/delimiters.html)。

## 保存、离线阅读与缓存

- OCR 保存完整离线 HTML 附件，目录内含 `ocr.md`、图片和本地 MathJax。
- 翻译保存完整离线 HTML 与独立 Markdown 附件，包含图片资源与本地公式渲染资源。
  不把依赖运行中服务的网页链接当作最终结果。
- 以后在 PDF 顶部选择 OCR 模式，或右键选择「查看 OCR 版本」「查看已保存译文」，直接读取附件。
  无需启动 Python、OCR 或翻译模型。已保存的 HTML 附件也可直接作为文件查看。
- 再次执行 OCR/翻译，会按源 PDF 内容指纹及目标语言复用已保存版本，不产生重复附件或服务调用。
  源 PDF 内容变化、目标语言改变时会保存新版本并保留旧版。
- 模型变化不会自动作废已有译文。如需重译，可先删除相应语言的译文阅读页与 Markdown 附件，再执行翻译。
- 使用 Zotero 原生导入附件，文件可随 Zotero 附件同步。新设备需先下载附件；同步容量和设置由 Zotero 管理。
  插件会从附件元数据恢复状态，删除本地状态缓存不会丢失已保存结果。
- 有父条目的 PDF 将结果存为同一条目的子附件；独立 PDF 的结果保存在相同文献库和分类下。
  群组文献库需要条目与文件写入权限。
- 失败不会导入残缺译文，已完成的服务端翻译单元缓存可供重试复用。
  公式、表格、代码保留；正文、标题、摘要、图注、列表等使用现有翻译引擎。表格单元格当前不翻译。
- 密钥保存在本机服务配置，不写入 Zotero 偏好、OCR/译文包或同步附件。
