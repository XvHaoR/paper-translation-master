# 阅读器模块与回归约束

0.3.1 修复了一个混合版本缺口：0.2.15 插件通过导航栏中的产品名称判断是否建立通信，
改名后的引擎生成中文页面时，旧插件只选中了页面段落，却没有向 PDF 发送定位动作。
这不是源 PDF 或已保存坐标丢失。另一个独立开关 `blockCompare` 只控制区域高亮，不能禁用定位。

## 模块职责

| 模块 | 拥有的行为 | 不应拥有的行为 |
| --- | --- | --- |
| `content/reader-protocol.mjs` | 固定协议、页面能力识别、动作类型、父层配置契约 | 识别产品名称、字号或 PDF 布局 |
| `content/reader-child.mjs` / `reader-parent.mjs` | 文档握手、消息传递、旧保存页兼容、已关闭文档的响应处理 | 根据品牌文字决定通信是否可用 |
| `modules/reader-session.js` | 当前 browser 的回调、连接状态、旧 frame 作废 | 字体、高亮或坐标计算 |
| `modules/reader-actions.js` | LaTeX、Excel、编辑、定位等动作分发，显式对照与本地文字选择分开 | 修改 PDF 绘制或页面样式 |
| `modules/reader-layout.js` | 单栏／双栏、左右交换、面板几何与宽度 | 通信注册、坐标解析 |
| `modules/reader-presentation.js` | 原生字号、主题、OCR 和译文外观 | 源 PDF 导航、高亮或通信回调 |
| `modules/reader-panel.js` | 工具栏、按钮和处理状态显示 | PDF.js 私有接口访问 |
| `modules/pdf-context.js` | PDF 初始化、原生对象和跨 realm 访问 | 高亮或品牌识别 |
| `modules/source-regions.js` / `pdf-regions.js` | 原文匹配、已有坐标校验、跨栏／跨页区域、PDF 导航矩形 | 设置字体或重启模型 |
| `modules/pdf-highlight.js` | 区域边框、背景淡化及清除 | PDF 导航或阅读消息通信 |
| `modules/comparison.js` | 双向定位流程、请求顺序、旧请求取消 | 字号、翻译展示方式 |
| `modules/reader.js` | 打开／载入／替换／移除阅读页的协调入口 | 将上述独立逻辑重新合并成一个通用更新函数 |

保留 `ReaderUI` 原有公开方法作为适配层，调用端不用随内部拆分一起修改。
插件 ID、偏好键、附件标签和旧消息名称保持不变，保存的 OCR 和译文不需重做。

## 兼容约定

- 新页面用 `data-reader-protocol="paperloom.saved-reader/1"`，并保留隐藏的旧识别标记供旧插件使用。
  新插件识别旧页面的 schema 或固定结构，不读取导航栏中的产品名称。
- 字体和样式可以独立更新，外观读取失败不改变通信是否可用。
- 显示模式决定 PDF 是否展示；普通文本选择不会强行展开 PDF，显式「对照 PDF」才展开。
- 高亮关闭后仍要双向定位。恢复高亮时使用当前已知区域，不重新 OCR 或翻译。
- 每个连接绑定当前 frame；每次定位有独立请求令牌。换文档、关标签页或新请求到达后，旧响应不得覆盖当前结果。
- 新文档的路径和元数据准备好后才替换旧文档，不能在异步准备中提前解绑仍显示的页面。
- 公式复制控件的生命周期独立于 MathJax 异步排版，排版完成或后续替换节点后仍可使用。

## 必须保持的回归

单元与集成测试覆盖协议、连接、坐标恢复、过期请求、样式异常和公式排版边界；
原生 Zotero 隔离文献库测试覆盖实际 PDF 与 HTML 的联动。测试不操作用户文献库。

```bash
python -m pytest tests/unit tests/integration -q
python tests/zotero/run_smoke.py
```

涉及阅读器的改动至少验证 OCR、逐段双语、仅译文，高亮开／关，原文／对照／仅 OCR，
连续切换与字号／字体／颜色更新，以及旧保存页。改名称或发布打包时，也必须保留协议与混合版本测试。
不能只确认页面能显示，必须断言 PDF 的目标段落与页面选择实际改变。

## OCR 与翻译调度

`Tasks` 为 OCR 和翻译各保留一个执行槽。不同 PDF 的任务可以并行，例如第二篇仍在 OCR 时，
第一篇已保存的 OCR 可以直接送往大模型翻译；OCR 后端的模型工作线程仍串行运行并复用模型。
同一 PDF 按提交顺序执行，不允许重新 OCR 与翻译同时读写该论文。批量处理不打开阅读页。
界面通过 `running` 获取全部活动任务，通过 `forSource(source)` 获取当前论文的活动任务，
兼容入口 `active` 只用于判断是否忙碌，不能用于查找特定论文。取消单项任务不停止共享服务。

回归必须包含：阻塞第二篇 OCR 时第一篇译文仍能生成并保存；同篇先 OCR 后翻译；
同篇已排队的重新 OCR 不被翻译越过；取消任一通道不影响另一通道；批量任务不打开标签页。

这套拆分和测试用于尽早发现回归，不构成永远没有缺陷的保证。新增功能应通过明确接口扩展，
有新失效路径时补相应行为测试，不能通过放宽原有断言绕过。

## 0.5.0 HTML 语义展示与编辑边界

`content/paper-layout.mjs` 只分组已有 DOM 节点，图片和说明、连续摘要可以共用容器，但不拼接 IR，不更改每段的 ID、坐标或已绑定监听器。
`app/services/paper_semantics.py` 只使用已有识别与 PDF 证据补充语义；人工校正的 source 快照绕过自动重分类。
`app/services/ocr_edit.py` 验证修改范围并保存新版本，类型修改不能改写身份和区域；已有附件更新编辑器不启动 OCR 或大模型。

DOM 回归覆盖连续图／表注、摘要分组、误判脚注改类型、编号／正文边界、重复增强、离线导出、类型保存与每段定位事件。运行前执行 `npm ci --prefix tests/dom`。
